ResidualV3 顶层设计 v2：用可见的 mismatch 线索选择修复动作
2026-10-12。研究设计，不是训练或评测启动计划。

当前正式验证的是E2单个通用repair头及其联合训练方法。96提示仅流程试跑，24条E2已见短序列留出不能支持/否定路线。最新用户要求数学/代码/对话每领域>=10000条实际头训练样本，冻结主体只训头；新方案总量>=42288（头训练>=30000，router6144、选型3072、独立留出3072），3种子，尚未启动。方案：../mismatch_expert_pilot_20261012_v1/LARGE_SAMPLE_PLAN_CN.txt。原E2和所有成绩保留，系统更新前不再启动GPU。

一、核心研究问题怎么改

原问题：能否用低成本残差头修复 target–draft 的预测差异？
新问题：在投机解码中，能否仅根据部署时可见的线索，选择对连续接受前缀最有价值的修复动作，并使收益覆盖选择与修复成本？

“可修复”是已有结果支持的基础。“不同状态需要不同动作、专家能互补、路由能省成本”是新的待验证假设。统一叙事应从 mismatch 的对象、可见信息、修复动作、接受收益、执行成本依次展开。

不要把论文主张直接改成“我们准确识别每个 token 的真实 mismatch 类型”。本轮 target 尚未验证时，真实 p 和首次拒绝位置未知；在线只能使用预测线索及上一轮已经发生的反馈。

二、mismatch 分清对象，路由分清信息

对象                     可以怎样使用                         证据边界
同一实际 prefix 的 p−q   teacher 监督/离线诊断修复方向          当前未来 p 不能作为在线输入；T0 argmax 差异另定义
块内条件差异             实际已选前驱/前缀重新条件化后续 proposal  当前 parallel body 未逐步吸收这些采样条件
跨轮条件变化             上轮拒绝边界、真实 bonus、已确认 prefix  是历史信息；不能保证旧 hidden 在新 prefix 上仍有效
训练–部署差异            检查 teacher-prefix 与自反馈状态覆盖    不自动导出增加昂贵 native 监督的方案

数学/代码/对话是评测任务类别，不预设为三种 mismatch 专家。T1 的一次随机拒绝也不能直接标注为“严重语义错误”。拒绝位置指示条件从哪里改变；替换 token 与已确认 prefix 才提供可能的修复方向，方向是否有预测价值还需测量。

若两个状态给 router 的输入完全相同，router 无法仅凭“多了几个专家”区分它们。需要验证已有输入是否足够，或明确新增哪一种低成本、部署可见的信息。不能将路由能力假定为免费获得。

三、第一版架构：一个共享主体，两个轻量专家，加 KEEP

已验证 prefix / 历史反馈
              ↓
      共享的五层 DFlash body
              ↓
      共享 raw/hidden 特征准备
              ↓
   当前实际前驱/前缀 → 轻量 router
              ↓
       KEEP 或专家 A 或专家 B（只执行一个）
              ↓
    实际 proposal q → 采样 → 普通 target 验证
              ↓
      提交有效 prefix/bonus，记录历史反馈

保留并冻结E2主体、target、embedding/LM-head和基底，避免每个专家重复运行全词表准备或body。只训练新的修复头内部投影/fusion/专家输出及router；共享特征准备不等于冻结所有头内可训练映射，旧试跑的仅suffix训练不是新的限制。所有新头写独立副本，不改原E2。

KEEP：沿用经过实际 sampling processor 的原始 proposal，不执行专家修正。它不是跳过 target 验证，也不等于跳过整块草稿。
专家 A/B：学习不同的有效修复动作。可把“局部概率校准”和“实际前缀条件修复”作为初始设计假设，但这些名字不是已发现的类别，也不保证两个头能分工。若互补性不存在，应保留单头方案。

router 的候选输入：raw/hidden 的共享低维特征、采样前概率统计、位置与温度、实际已选前驱，以及上轮已经可见的拒绝/bonus 信息。若增加完整 prefix 摘要，须明确它的信息增量与计算成本。q45 仅有概率统计且无 token 身份，不能单独提供语义方向。

先采用确定性 top-1 路由：第 j 个候选采样前，a_j = g(X_j)，a_j ∈ {KEEP,A,B}。
实际 proposal 为 q_j = sampling_processor(raw_logits_j + Delta_{a_j}(X_j))，Delta_KEEP = 0。
先选动作、再执行该专家、再采样 token；不得把多个专家采样后的 token 挑选结果仍冒称某个原专家的 q。后续若改成概率混合，需另定义真实混合分布并验证采样合同。

专家总参数量可以增加，但每位置激活工作应接近一个小头。共享准备、router、prefix 摘要、专家分组、映射、kernel launch 和 Graph padding 都要计时。“只激活一个”不保证 C32 更快；若底层仍算两个头再 mask，便没有稀疏执行收益。

四、优化目标服务连续接受前缀

路由应选择预期增加的连续接受 token 值得付费的动作，而不是选择 entropy 最大、p−q 最大或置信度最高的专家。

对于同一实际 prefix 的随机采样分布，单位置 overlap = sum_v min(p(v),q(v)) = 1−TV(p,q)。整块 AC 取决连续 prefix 的生存过程与后续条件变化；不能把各位置独立 overlap 的简单乘积当真实 rollout 概率。

概念上的决策价值：新增的预期连续接受收益 − lambda × 选择/修复/执行的额外时间成本，lambda 用于统一量纲，须由实测成本与明确的优化约束确定。
最终目标是完整服务同窗 TPS，离线局部 KL、overlap、teacher-prefix OUTPUT 或模拟 oracle 只作代理诊断。E2 q45/latent 的 teacher-prefix 标签不是实际 native 生存概率，不能直接当可靠路由标签。

新增专家的训练目标必须单列方案。先检查既有校准数据和诊断信息是否足以研究互补性；若不足，明确缺少的证据，不自动新增昂贵 teacher/native rollout 数据，不开启 epoch3，不改写现有 E2 损失或训练履历。

五、主体与 target 的第二条贡献如何接上

上述第一版仍然完整运行五层 body 和普通 target 验证，属于修复模块升级。单凭多专家头不能主张“压缩主体时间”或“压缩 target 时间”。

后续主体候选：上一轮已观测的条件变化 → 判断重叠位置复用、廉价修复或必要重算 → 在相应输入上选修复专家 → 形成实际新 proposal。
只有实际减少 query body/原始 LM 工作，且缓存/映射/修复和额外验证没有吃掉收益，才成立主体成本贡献。这里复用的是近似 proposal 信息，不能当新 prefix 下精确 target hidden/KV。

target 候选保持独立：把有效验证 prefix 变成真实紧凑执行，消除固定 padding 与读回等待。路由修复专家本身不缩短 target 执行。先完成 C1/C32 实际混合长度关键路径归因，再决定是否值得联合设计；避免同时混入头路由、body 缓存和 verify 调度后无法归因。

七、最小实验闭环与停止条件

1. 先确认可见线索与修复动作的异质性，并明确既有数据的覆盖。若没有低成本可识别的差异，不训练复杂 router。
2. 在独立候选版本研究两专家互补性；比较当前通用头、最佳单专家和训练/总参数预算匹配的更大单头。target 可见的 oracle 只表示离线上界，不是部署模型或新测速结果。
3. 有互补性后再研究可见输入的 top-1 router；比较固定/随机路由、学习路由、无 KEEP、仅 KEEP 开关、无历史反馈。分别控制总参数预算与激活计算预算，判断是专家分工、容量增加还是 KEEP 的贡献。
4. 新冻结推理实现先过实际 token、前驱、所选专家真实 q、bonus、请求结束、KV commit/rollback、CUDA Graph 合同，再做 C1=16/C32=80、max256 短测。若改变 KV 实现，增加独立 KV 字节/有效位置比较。
5. 有稳定净收益再扩正式三领域评测。body 复用另设同主体机制对照：始终重算、固定范围复用、仅信息反馈、动态复用。正式方法基线仍为独立单训 DFlash；同主体消融用于归因。

T0 检查 target greedy 输出一致；T1 使用真正采样的 proposal 分布与同一实际 prefix 的 target 分布作接受/拒绝残差校正。T1 同种子逐 token 相同不是分布正确性的必要条件，也不能只凭 aggregate AC/TPS 宣称正确。基础机制见：https://proceedings.mlr.press/v202/leviathan23a.html

若在充分样本与受控对照上专家互补性弱、router无法预测、或C32执行成本吞掉收益，再停止扩展。96条流程试跑不能作为该停止条件的有效证据。原E2/主体冻结；大样本方案尚未执行，native吞吐和跨轮/body/target候选仍未实施。没有稳定截断净收益不新增截断长测，系统更新前不启动GPU。

九、目前可用的论文动机段

并行草稿以一次主体前向产生多个位置的预测，但后续位置的实际采样前缀，以及验证后更新的条件，可能与这些预测所依据的信息不同。我们的 E2 结果说明低成本残差修复能够提高连续接受长度和服务吞吐。下一步研究的问题是：这些可修复差异是否存在由部署可见信息区分的结构，是否适合不同的修复动作，以及稀疏选择这些动作能否在受控成本下超过单一通用修复器。若成立，再研究这种选择能否支持草稿表示的复用和必要重算。

这段将“已有单头结果”与“下一阶段假设”明确分开。待新实验成立后，才能把“研究是否”改成“方法实现了”。
