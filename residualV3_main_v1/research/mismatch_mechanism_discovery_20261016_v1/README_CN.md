# 下一步：找出一个具体的失配问题

本包要回答：**在什么明确条件下，低成本草稿会稳定地犯哪一种错；哪个具体近似环节可能造成它；有什么观测能把这个解释与其他解释区分开？**

执行 chat 要实际分析已有数据，最后交付最多一个值得受控检验的小切口。不能只换一个 mismatch 名称，也不能把已有修复收益当作原因。候选全部不成立时，明确停止推荐，不自动追加一轮。

本包取代此前 `MECHANISM_SOURCE_SCAN_20261016_CN.md` 中“优先研究输出适配”的建议。输出层、监督、条件信息等都只能作为竞争解释，尚未选定任何一个作为论文主线。R1–R9及原报告保持归档。

## 执行顺序

1. 核查原论文如何从具体异常提出解释；汇总本地已知结果与负结果。
2. 用 R8 全部36题旧概率存档，检查具体错误落在哪里。禁止按原头成败选样本。
3. 从结果中冻结最多3张候选卡；每张写清必要预测、竞争解释及不同预测。每候选最多2项诊断。
4. 选出最多1个小切口，写出一个能区分解释的受控检验；本包不启动新的训练。没有候选通过也可以完成。

## 本轮边界

这是**回顾性的机制发现与候选淘汰**。它能检查必要现象、排除部分解释、明确下一次改变什么因素；不能仅靠旧概率确认训练或模型规模的因果。

收到启动 prompt 后可自主完成本包规定的 CPU 工作。所有 run 合计：6 CPU进程树小时、8 GiB新增磁盘、16 GiB自有RSS；GPU为0。现有数据足够开展这一阶段，不等卡、不加载模型。旧资产只读，不训练、不采新题、不改安装环境。

写作包完成不代表实验完成。新执行结果写到本目录 `runs/<UTC>_mechanism_discovery/`；不续写旧run。只有后续受控检验得到直接证据，才决定论文主张和推理架构。
