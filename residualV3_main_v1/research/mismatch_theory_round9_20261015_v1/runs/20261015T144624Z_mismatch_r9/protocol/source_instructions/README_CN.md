# 第九轮：直接研究失配的可修边界

**这轮不再问某个头或探针是否有效，而是问：固定一组真实失配，任何共享修正最多能做到什么；哪里确实需要区分历史。**

同一组target需求和raw预测，分别计算最大平均改善、每条都改善的幅度、保证每条不恶化时的平均改善。三者分开后，才能区分“这个方法没做好”和“这个信息条件下确实无法兼顾”。随后保持p/q不变，只改变允许区分的历史，检验限制如何改变。

主要文件：

- [理论与研究方案](THEORY_PLAN_CN.md)：问题、边界、直接对照和正反结果分别如何回答问题。
- [执行指南](EXECUTION_GUIDE_CN.md)：数据、数学算法、证书、固定面板、统计和资源。
- [给执行chat的完整prompt](START_PROMPT_CN.md)：复制分隔线以下全文。
- [核心问题审核](qa/CORE_QUESTION_REVIEW_CN.md)：哪些初稿不合格、如何修改、最终判断。
- [数学与执行可行性审核](qa/FEASIBILITY_REVIEW_CN.md)：公式、证书、输入身份与工作量核查。
- [固定参数](protocol/DESIGN_SPEC.json)和[只读输入盘点](qa/INPUT_AUDIT.json)。

仅使用R8已暴露完整概率存档做CPU研究：没有新鲜留出、没有训练、没有GPU任务。编写时只做了资料/元数据核查和小词表数学可行性检查，没有运行本轮模型数据效果分析。

与旧轮次的区别：R1已做KL分解，R4已做受限操作的共享/安全oracle，本轮不能重复包装。此轮去掉操作范围限制，以完整simplex认证**纯信息合并**的剩余边界。它能回答这一机制及有限族可修条件，不能从固定checkpoint推导模型规模、训练数据或优化的因果责任。

固定任务结束后停止。研究方案通过审核不表示实验结果为正，也不表示ACL创新性已经成立。
