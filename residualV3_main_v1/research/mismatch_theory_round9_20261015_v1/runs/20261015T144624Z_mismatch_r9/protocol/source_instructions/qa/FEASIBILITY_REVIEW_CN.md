# 数学与执行可行性审核

结论：**通过方案级审核**。审核对象为当前 `THEORY_PLAN_CN.md`、`EXECUTION_GUIDE_CN.md`、`START_PROMPT_CN.md`、`protocol/DESIGN_SPEC.json` 和 `qa/INPUT_AUDIT.json`。通过不表示科学假说成立，也不表示执行代码、完整词表数值合同或正式CPU工作已通过。它们仍须按执行指南完成准入。

## 1. 核心数学已区分三个不同问题

- A是允许损伤时的最大平均改善；M是每条历史共同改善的最大保证；S是逐分支安全约束下的最大平均改善。加入S解决了“不能人人严格变好”被误读为“任何平均改善必伤人”的问题。
- 数值主量明确为逐分支容忍损伤不超过 `tau=1e-7` 的S^tau，严格S与S^tau没有混称。只有超过S^tau有效上界的收益才要求至少一分支损伤超过tau。
- 同一target面板的R只依赖target需求和信息分组，与D/J raw主体无关；两个主体只改变E、A和相对raw的M/S。文本已保持此身份。
- full-simplex允许任意概率向量；本轮只识别有限历史族下的信息约束，不识别模型规模、训练或真实basis可达性。R4的受限尾形状oracle不能直接代替本轮求解器。

## 2. 闭式与小型专用计算

均匀经验频数平均TV的共同分位阶闭式正确。重复自然slot展开等价于原频数权重；不同H等权是单独辅助测度。公共次梯度 `d=(2*k-n)/(2*n)` 给出 simplex上的共同仿射下界。n=1、所有target相同、相邻分位质量都等于1时的退化处理均已列出；`F(a_k)`在非单位质量处只是L1凸函数，文本没有把它作为概率候选。

双target的M闭式及线段见证正确，依赖两项原始距离来自同一个q；反三角不等式保证混合系数合法。双target的严格S及S^tau线段端点公式亦正确：任意外部候选的两项距离都能被该线段上一点同时不增地替代，再在线段上的合法区间最小化加权线性损失。

审稿期间保存并执行了仅使用合成小词表的独立检查：[reviewer_math_check.py](reviewer_math_check.py)，结果为 [MATH_FEASIBILITY.json](MATH_FEASIBILITY.json)。60组平均风险例的最大LP差为2.22e-16；60组pair例的M和S/S^tau最大LP差均为1.11e-16。单点、重复、零、ties及两个指定多target反例均相容。此检查未读取模型概率或科学效果，不替代正式执行阶段的完整数值合同、tail LP对偶证书、完整词表guard及资源准入。

## 3. 多target证书和安全性

active+tail桶对完整TV是收缩，因此在保留完整原始d_j时产生M、S^tau的外层上界；不能将原始d_j一同压缩。任意合法完整tail重构满足 `0 <= TV_full-TV_bucket <= p_j(U)`，故M的完整见证与桶最优之间可用最大target尾质量、优化gap和数值guard控制。

S^tau不享有仅凭桶可行就得到完整可行的结论。当前指南已要求完整分支检查，并允许在有严格正margin见证时按凸性混合恢复安全；否则保留raw零下界。该条必要且正确。求解失败、支持集上限或间隙过宽均保留区间，未被解释为不可修。

平均最优动作可能不唯一，其受损率不能代表必然受损率。当前文本以S^tau上界和A−S^tau的证书判别取舍，避免了该误判。对子组的R/S加权、M取最小值及区间单调聚合均正确。

## 4. 信息对照与采样身份

R随信息细分不增、IH风险为0均是数学性质；i3最近两token即完整H，当前方案正确限定其为控制。16次固定假分组仅计算R，且使用不同H等权并保持组大小；I2在真实I1内置乱。没有把该对照扩展成M/S的组数效应排除证据。

只读核对源 `code/common.py`、`code/collect_r8.py`：存档logits以BF16位模式保存，target行通过META的target_row索引，同H复用target；D/J raw按位置固定，F只是历史来源。执行时须复用该位模式解码及原FP64概率构造的实际口径，不能将uint16位模式当数值logit直接softmax。概率文件SHA、实际消耗范围仍由执行阶段核验，审稿没有声称已重验全部概率文件。

## 5. 工作量与资源边界

已独立仅以META重算固定12题、anchor1面板，结果见 [METADATA_FEASIBILITY.json](METADATA_FEASIBILITY.json)：108个target面板、216个raw面板；I0/I1/I2分别有79/218/149个至少三种H的组，合计446组，双raw共892个一般优化组，与INPUT_AUDIT一致。

892组每组两目标合计60秒（各30秒，包含全部active阶梯）的solver wall理论上限约14.87小时。单数值线程下，24小时CPU总限仍留有约9小时用于解码、排序、sham、组装、审计与报告，但这不是实机性能保证；必须依指南先做固定dev计时，并把组装和完整词表重算计入总预算。所有一般组即使区间未闭合仍应留分母；不能挑易解组完成。

16GiB新增磁盘与32GiB峰值RSS可通过逐context流式解码、复用target风险及紧凑可重构见证实现。无需保存每个sham/每个平均解的完整V维副本；使用输入SHA、分组映射、k/alpha或active值、tail质量和形状引用即可完整复核。6个展示案例才需要独立完整词表账本。不得为缓存方便复制整套旧概率存档。
