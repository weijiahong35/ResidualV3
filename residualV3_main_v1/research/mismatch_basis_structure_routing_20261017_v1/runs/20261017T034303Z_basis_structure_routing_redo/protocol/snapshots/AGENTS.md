# 项目长期协作约定

## 失配研究的核心问题（用户明确要求）

研究对象是大小模型之间的失配（mismatch）本身：

1. 失配如何形成，哪些解释有证据，哪些仍是假说？
2. 什么样的失配可以被修复，为什么可以修复？
3. 什么情况下修复会失败，失败来自失配本身的限制，还是某个具体方法没有修好？
4. 这些认识如何推导、解释或约束修复方法？

理论与方法分开。AR 修复头是方法实例；不能把核心问题自行替换成模块消融、原头成败预测、指标相关性，或反复验证某个探针的平均收益。具体方法的失败不等于失配不可修；存在一个有益探针也不等于已经解释了失配。

## 每份研究方案必须经过核心问题审核

用户于 2026-10-15 明确要求：

> 每次写完方案就要审核是否回答了核心问题，如果回答不了就重写，直到回答为止。

适用于研究方案、实验设计以及交给执行 chat 的指引和启动 prompt。完成草案后、交付为可执行方案或启动实验前，必须逐项检查：

- **问题对应：** 用用户的核心问题表述本次要回答什么，不自行换成更容易得到阳性结果的代理问题。
- **直接证据：** 说明计划中的对照与观测如何区分关于失配的竞争解释，如何回答形成、可修复性、修复原因或失败边界。不能只列指标和实验步骤。
- **结果判别：** 事先说明不同结果分别支持、反驳或仍无法区分什么。若无论结果如何都无法回答所声称的核心问题，方案不通过。
- **排除绕路：** 每项实验说明其必要性；只检查工程、预测原头表现或重复探针收益的工作，须标为辅助，不能代替核心研究。
- **已有证据：** 核查已完成实验，说明还缺哪条直接证据；不重复已回答问题，不忽略负结果，不把标准数学恒等式当新理论。

审核结论必须随方案保存，明确“通过/不通过”、理由及修改内容。**不通过就重写，再审核，直到方案能够回答其声称的核心问题；不得把不通过的方案交给执行 chat 或用实验次数代替重写。** 不需要反复请用户确认已明确的核心方向。

“能够回答”指设计能形成有效判断，也允许否定结论；不指保证假说成立。不得通过事后换指标、筛题、改阈值或反复追加实验追求阳性。若当前条件无法设计出有效检验，应直接说明具体缺口，不能假装审核通过。

方案审核通过不自动产生超出用户当前授权的训练、GPU运行或资产修改权限。继续遵守当次任务的资源与资产保护约束。
