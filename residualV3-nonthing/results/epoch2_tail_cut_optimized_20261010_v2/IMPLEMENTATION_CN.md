# 第二轮尾部截断的实现优化

这次固定第二轮DFlash、三层no-soft repair、q45/末层两个辅助MLP以及原校准阈值，仅修改推理实现。正式对照仍为独立单训DFLASH、FULL15、Q45_CUT、Q45_LATENT_CUT；GSM8K nonthinking，C1=200、C40=1319，T0/T1，block16=anchor+15 proposal，max_new2096/context4096，BF16。

即时日志：[C1 smoke](single_card_C1_smoke.log)、[C1正式](single_card_C1_formal.log)、[C40 smoke](single_card_C40_smoke.log)、[C40正式](single_card_C40_formal.log)。[实时结果](RESULTS_CN.md)和[状态](status.json)由CPU报告进程维护。

## 已修改的工作

1. Target图：C1捕获1–16行对应的piecewise图，完整16行仍用原full图；C40保留所有原uniform full图尺寸，ragged总行数最多补7行。正式窗口记录逻辑行数、图行数、full/piecewise次数，不能只凭配置宣称省计算。
2. 停修后的特征和采样：设备端读取alive掩码，已停止请求不再扫描其词表计算q45，也不再产生其尾部采样。保留前缀使用vLLM原gumbel_block_argmax、1024宽tiles、seed/位置及FP32/FP64设置。未提交尾部的processed q不写入；校验逐位检查所有实际提交的q和token，并确认调度器收到的前缀与之相符。
3. q45：利用BF16离散值做两级直方图，恢复精确Top256值；只排序最多255个边界以上的值。保持原8192宽度的熵/normalizer归约及running-max递推，q45定义不变。大批次保证未停止的前10位置采用计时更快的原stock TopK，其后才使用设备端跳过；C1始终使用新内核。
4. 冻结预测权重：在捕获图前一次转换成BF16，避免15个位置反复autocast权重。原FP32权重通过autocast产生的BF16操作数和输出均单独核验相同。

一位置延迟、最少修8位置、patience2及累计生存概率策略均保持原样。主流等待预测j−2的依赖仍保留；通过加快预测减少等待，没有删除必要依赖。头的prepare和部分归一化、小kernel发射槽仍保留，不能宣称停止后所有开销为零。

## 已完成的GPU校验

- [171项特征和采样检查](FAST_KERNEL_GATE.json)：N=1/7/40，均匀、普通和极端logit尺度；混合/全部/无活跃行，T0/T1/.9、FP32/FP64 Gumbel。有效位置q45、采样token和processed q逐值一致；无效行q未被写入；同一CUDA图切换预热标志0→1→0时，真实请求跳过尾部，内部预热填写完整q，均与stock采样一致。
- [40个完整block案例](MICRO_GATE.json)：N=1/7/18/40，T0/T1，强制15/12/10、禁用截断及高风险策略；原始头递推与有效前缀logits/token/实际前驱/q一致；单流、双流与CUDA图状态一致。还核验3000次有效位置的原预测分数和maxq一致。
- [两支读出缓存检查](AUX_READOUT_GATE.json)：原FP32参数在autocast下与预缓存BF16参数输出一致，共6项，覆盖q45和q45+末层表示。

服务smoke发现两个集成边界，已修正：无头DFLASH/FULL15的校验分支需要保护；vLLM内部预热直接提交完整15-token验证块，绕过真实请求的截断调度，必须填写完整processed q。后者使用可变GPU标志，只有内部预热覆盖停修掩码；真实请求保持设备端跳过。失败日志和原协议保留在[第一次](service_startup_failed_01)和[第二次](service_startup_failed_02)归档。

直接调用micro脚本时曾漏掉VLLM_BATCH_INVARIANT=1，造成参考头与优化头使用不同的归约内核。脚本已强制检查该设置，失败记录保留；正式服务的原启动配置本来就启用了固定归约。重新对齐设置后，40个完整block和3000次读出比较已全部通过。C1/C40×两种截断模式×T0/T1的8个服务窗口已通过，[服务校验记录](SERVICE_VALIDATION.json)记录逐值校验和实际target图行数。C1已开始200题正式测评；C40在补完不变的基线smoke后自动进入1319题正式测评。

## 正式结果与流水线控制（2026-10-11）

C40正式8个窗口已全部完成。相对同温度FULL15，Q45_CUT的T0/T1接收长度分别下降0.359%/0.301%，TPS下降6.920%/5.835%；Q45_LATENT_CUT分别下降0.330%/0.005%，TPS下降7.468%/5.914%。固定阈值下这版尚未取得截断的端到端净收益；之前“相对旧截断实现更快”的微计时不能替代这个比较。C1正式仍在运行。

独立探针进一步分离了成本：[流水线控制报告](probes/wait_path_20261011/RESULTS_CN.md)，24项一致性检查、72项计时。C40/T0合成状态下，完整15位置6.5009 ms，预先知道停在10位置且不运行预测6.2422 ms，单流预测9.4618 ms，当前双流预测8.5458 ms。流水线已有部分重叠，但剩余预测开销大于节省的修复时间。

去掉保证继续的早期位置等待，几乎没有收益；再去掉最后两次不影响当前proposal的预测，强制10位置耗时降至8.4400 ms，仍比完整15位置慢。有效前缀logits、token、前驱、原生q及截断决定逐值一致。该修改仅存在于独立探针，未中途替换正式测评实现；不能宣称正式吞吐已经修复。
