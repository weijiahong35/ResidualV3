# 本次推理实现修改与磁盘整理

模型、三层 no-soft 修复头、epoch2 q45 预测头和截断阈值均保持不变；没有改训练目标或训练梯度。所有运行使用冻结源代码和校验记录。

## 已落实并校验的修改

| 修改 | 校验 | 收益的范围 |
|---|---|---|
| 有效前缀边界留在 GPU，消除 CPU 等待长度读回 | 微测及真实采样器/修复后 q/截断一致性 | 单并发截断原约 8ms 的读回等待消除；短测 TPS 损失从约 10% 缩至约 1% |
| 保留原 PyTorch L2 范数，融合方向和幅度后处理 | 127组组件、12组完整头，含真实失败边界样本 | 同窗完整头微测 N1 T0 2.029→1.873ms，N40 T0 6.498→6.324ms |
| 原采样器输出未加噪 logits 最大值，供 q45 复用 | 12组完整头及真实 smoke | 完整头微测约0.05–0.86%时间缩短；单独短测仍无截断净 TPS 收益 |
| 前驱编码表查找与分支拼接合为一次拷贝 | 12组完整头及真实 smoke | 单并发完整头约1.6–1.9%时间缩短；多并发接近不变 |
| 图外保留的六个状态拷贝合为一次 kernel | 24组逐字节拷贝、12组完整头/同实现图状态 | 单次状态保存11→4μs，完整头约0.1–0.4%时间缩短；最后短测未体现稳定额外优势，不选用 |

完整头计时是冻结模型的组件微测，不能直接写成端到端吞吐收益。不同改动的百分比来自各自同窗对照，不能相加或用跨轮 TPS 得出增长。

## 不采用的方案和校验失败记录

- 完整融合 L2 范数：随机微测通过，但真实 C40 FP32 归约差9.54e-7越过BF16分母舍入边界，413个方向值不同。恢复原范数归约，保留失败样本和复核代码。
- 活跃请求集中计算：数值校验通过，完整实现更慢；不接入。
- 调缓存分块：缓存算子更快，完整头慢约0.05–0.35%；核对存档后删除开发原型。
- target 输出投影按有效长度分组：统一cut10微测较快，混合长度较慢；不接入。
- 全状态拷贝初次校验：误把v3全部状态与多算末两行辅助预测的旧v2相比；保留原有效输出校验，新增同v3 eager/graph状态及逐字节拷贝验证，没有放宽有效 token/q/截断门槛。

## 当前实现的边界

有效前缀边界由 GPU 采样器执行；target仍运行固定补齐图，没有物理压缩 target 全部计算。修复 MLP 每16个请求共享计算块，只要块内仍有未停的请求，该块的矩阵计算就会执行；单个请求提前停不保证同比节省 MLP 时间。活跃请求压缩原型已经测过，当前版本没有得到更快结果。

最后同窗结果与每轮即时 log 见 [短测总表](RESULTS_CN.md) 和 [主状态](status.json)。这些是 C1 16题／C40 80题、max256 的实现短测；正式评测题数与正式基线不变。
